# Forges Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pull requests, clone and publish on GitHub, GitLab and Gitea/Forgejo through each forge's own CLI, with a Settings → Forges status page.

**Architecture:** A `ForgeDriver` per forge (`gh`, `glab`, `tea`) behind one interface in `apps/server/src/forges/`. `PullRequestService` keeps its Git work and asks the driver picked from the worktree's `origin` remote for the forge work. New `forges.*` and `project.clone/publish` RPC commands answer outside the event log, like `review.pr.*`.

**Tech Stack:** TypeScript, zod contracts (`packages/contracts`), Node server (`apps/server`), React 19 web (`apps/web`), vitest, Playwright e2e.

**Spec:** `docs/superpowers/specs/2026-11-17-forges-design.md`

## Global Constraints

- All paths below are relative to `v2/`. Verify with `pnpm run verify` (baseline: 0 errors, 20 lint warnings).
- CLIs run only through `ProcessRunner` (no shell), with timeouts; every shown error passes `redactSecrets`.
- Contract changes are additive only. GitHub keeps returning `gh_missing`, `gh_unauthenticated`, `gh_failed`.
- Minimum versions: `gh` 2.40, `glab` 1.40, `tea` 0.9. Older → status `outdated`.
- Forge kinds: `github` (`gh`, `gh auth login`), `gitlab` (`glab`, `glab auth login`), `gitea` (`tea`, `tea login add`). Well-known hosts: github.com, gitlab.com, codeberg.org (gitea).
- GitLab's request noun is "merge request"; the others "pull request".
- UI copy follows the antislop rules in `AGENTS.md` (applied during the work).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No push.

## Review Focus

1. A remote on a host no CLI knows (e.g. `git.company.internal` with no `tea`/`glab` login): Review pane shows push and no broken PR card; problem code `unknown_forge`.
2. A CLI installed but signed out, or older than the minimum: status says which, with the command to run, and PR actions are not offered.
3. `origin` missing but another remote present: detection uses the first remote, as `readProjectRemotes` already orders them.
4. CLI output that isn't the expected JSON (old version, HTML error page): `cli_failed` with a readable message, never a thrown parse error.
5. Clone into a folder that already exists and isn't empty: refused before running git, with a message naming the folder.
